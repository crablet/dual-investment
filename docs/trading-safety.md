# 实盘交易安全

## 账户与自动处理范围

- **专号专用。** 连接后，客户端自动同步 Binance 当前 BTC/USDT 卖方 Put/Call 净持仓，并为符合下述条件的仓位自动执行到期现货交割。买方持仓不在处理范围内。新卖出委托仍必须由用户在“双币赢”页复核确认。
- **只有到期前已成功同步到本地、且未结束跟踪的持仓，才能生成交割任务。** 同一合约的加仓、减仓和买入平仓按当前净仓更新；到期前确认持仓已清零或变为买方后停止跟踪。
- 首次同步时已经到期的合约不登记，不根据历史成交或历史行权记录补建交割任务。例如 16:00 到期、16:30 首次连接，该合约不会自动补交割。
- 到期前已跟踪的持仓可以在离线跨期、重启后继续恢复。到期后持仓从 Binance 列表消失，不代表本机交割任务完成。最终交割数量必须由该账户的卖方行权记录确认，最后一次仓位数量只供核对。
- **不要在客户端之外手动补交割，也不要用同一账户混做其他策略。** 程序不会识别手动现货交易的用途；离线期间手动补齐已跟踪的义务，重启后程序仍会继续执行，可能造成重复买卖。客户端不提供手动补齐识别、余额用途推断或补偿操作。
- 每份本地 SQLite 数据库绑定一个 Binance 账户 UID。两种连接入口均在维护锁、交易锁内核对归属，通过后才更新凭据和当前连接；不同账户被拒绝，同账户更换 API Key 可继续使用原记录。UID 来自现货账户查询，缺失或无效时连接失败。删除凭据不解除数据库绑定；清空数据库会丢失跟踪与恢复记录，不能用来处理未完成的交割。

## 同步与串行

- 连接和“同步”只读取交易所事实、保存持仓及待处理任务，不发送交易或资金请求。后台维护可自动推进已登记仓位的到期交割与资金收尾；重连不重复授权。连接验证期权及现货权限，凭据、权限或账户状态错误时暂停自动重连。
- 净仓在连接、期权下单/恢复成功后同步，后台每分钟尝试同步。查询失败时保留上次成功的数量与更新时间并显示错误，不把接口错误当成空仓；已登记仓位到期后仍可先根据本地记录生成待确认任务。请求跨过到期时刻才返回时，不新增该已到期合约的跟踪记录。
- 页面读取本地快照；账户估值展示独立刷新，失败时保留上次成功的数据。展示缓存不参与下单、备资或恢复判断。
- 账户展示刷新单独串行，查询过程不持有交易或维护锁；后台已有展示刷新时跳过，不排队堆积。断开或更换连接后，旧连接返回的结果不会写入当前缓存。
- 维护共用维护锁，交易与恢复共用交易锁；取锁顺序为维护锁 → 交易锁。恢复记录在锁内重读和更新，后台繁忙时跳过。

## 界面语言与消息

- 语言偏好只影响展示，切换语言不会重新挂载业务页面或触发连接、下单、资金与恢复操作。词典加载失败时保留当前语言，启动阶段词典加载失败时回退英语；语言加载失败不进入业务自动重连流程。
- 订单、交割、恢复、进度和错误消息通过 [Message](../src-tauri/src/messages.rs) 保存稳定代码与安全参数，在前端展示时翻译。参数中的金融数值保持 Decimal 字符串；日志与翻译结果均不能作为成交或资金事实。
- 重试和恢复依据后端结构化错误及记录状态。前端只接受经过校验的 `canAutoReconnect` 资格，翻译文案不能赋予重试许可；Tauri 传输错误或消息格式异常不授予自动重连资格。实现见 [errors.rs](../src-tauri/src/errors.rs) 与 [api.ts](../src/services/api.ts)。

## 下单与交割

- `preview_strategy` 只按方向、执行价、候选限价和输入数量进行本地 Decimal 计算，不读取账户或发送交易所请求。输入变化后旧预览失效；复核弹窗固定候选、数量和对应预估，预览成功不代表已通过实时交易检查。
- 后端核对用户确认的合约条款与数量，重查价格/数量过滤器和买一盘口。IOC 仅使用买一，量不足则停止。
- 已成交回报必须有有效成交均价；现货可由累计成交额和成交数量推算。不能用委托限价替代成交事实，提交后的回报解析失败按待确认结果处理。
- 卖 Put 至少覆盖名义本金，卖 Call 按 Binance 合约保证金参数备资，同时满足可用余额和权益缓冲。
- 备资与归集目标为 90%；最终下单校验另有 5 个百分点容差，硬上限 95%。容差不得减少备资或扩大归集。参数见 [margin.rs](../src-tauri/src/strategy/margin.rs)。
- 委托历史、当前净仓和交割任务分别保存。同一合约只有一个到期任务，历次卖出成交量不会累计为交割数量。任务按同标的、同到期时刻组成批次。
- 账户行权记录按合约、卖方方向、期权类型和到期时间核对，按记录 ID 去重，使用确认后的数量、结算价与现金结算金额。完整性不足时等待；记录互相矛盾时停止推进。历史记录只能确认已有任务，不能创造新任务。
- 同标的、同到期时刻的公开结算价可以确认未价内到期、无需现货交易，但不能证明本账户的最终数量或现金流。此时任务可标记完成，未取得账户记录的数量和现金金额仍保留为空；价内却没有账户行权数量时继续等待，不以缓存仓量下单。
- 现货交割量为 `账户行权合约张数 × 每张合约标的数量（unit）`。卖 Put 买入 BTC，卖 Call 卖出 BTC。每笔现货成交必须足额确认；任务完成后不再产生新现货订单。

## 资金与恢复

- 只补真实缺口：开仓先用现货，再赎回活期；接货 USDT 依次用现货、期权可划余款、活期。每笔发送前重查余额，不预支未到账金额；接货不足则等待后台复查。
- 备资只查询有缺口资产的活期持仓；账户概览另行读取活期、定期和估值信息，定期理财查询不参与备资流程。
- 按整批尚未交割的 BTC 数量预留资金：Put 为 `结算价 × 剩余 BTC 数量 × 1.02` USDT，Call 为剩余 BTC 数量。已发送现货请求的剩余数量只用于计算资金占用，不能据此补发新订单。计算见 [funding.rs](../src-tauri/src/app_state/funding.rs)。
- 未完成的到期义务与批次保留资金并阻止新策略和无关资金动作。交割任务完成后，批次仍可能处于资金收尾阶段；整批交割完成至少 5 分钟后才归集，期间继续预留资金并保留其他仓位保证金。尚未开始的归集等其他到期义务完成，已登记的资金计划优先完成，批次间不得挪用预留。
- 发送前保存唯一恢复关联和固定资金计划；现货客户端订单号、交割任务与恢复记录原子落库。资金经交易所历史唯一确认并实际到账后才继续。
- 请求未确认或历史匹配不唯一时，阻止新交易和资金动作，只查询原请求，不重发。现货终态成交不足或异常须人工核对；仅已阻断的资金记录可在人工核实后标记结果，解除阻断不重发。
- 重试与恢复依据结构化错误类型、HTTP 状态和交易所错误码，规则集中在 [errors.rs](../src-tauri/src/errors.rs)。查询的短退避规则不能用于重发订单或资金请求；POST 仅在明确收到时间戳拒绝码 `-1021` 时校时后重试一次。
- 日志写入失败只在日志面板反馈，不改变已确认的交易或资金结果；恢复记录、净仓和交割任务的必要数据库写入失败仍会阻止后续业务。
- “结束理财收尾”仅限已阻断且交易、划转均已完成、无未确认请求的批次，由用户确认。只关闭批次并解除预留，不改变成交或资金结果、不发送请求；完整条件见 [settlement_recovery.rs](../src-tauri/src/app_state/settlement_recovery.rs)。
