# 使用指南

[返回项目首页](../README.md) · [实盘交易安全](trading-safety.md) · [开发指南](development.md)

双币赢助手通过 Binance 期权与现货执行 BTC/USDT 双币赢式策略。新期权订单由用户手动确认；连接后自动同步卖方净仓，并对到期前已登记的义务执行后续交割与资金收尾。

## 连接与界面设置

设置页上方左侧为“Binance 连接”，右侧为“通用设置”，日志位于下方。

API Key 关闭提现权限，仅授予所需的读取、现货与期权交易、Simple Earn 和 Universal Transfer 权限。凭据保存在系统 keyring，不保存在 SQLite 或日志中。Linux 需要可用的 Secret Service / keyring 服务。

请使用专用账户运行此策略。每份本地数据绑定一个 Binance 账户；首次验证时建立绑定，之后只能连接同一账户。同账户更换 API Key 可继续使用原订单、净仓和交割记录；连接其他账户会报错并保留原连接，删除保存凭据也不会解除数据绑定。

启动时会尝试使用 keyring 中已保存的凭据连接。连接成功或点击“策略订单 → 同步账户”会读取交易所状态，自动登记当前未到期的 BTC/USDT SHORT 卖方净仓，不包含买方仓位。

后台每分钟尝试维护订单、净仓与交割任务，前端定时读取本地快照更新显示。需要立即核对交易所状态时，使用“同步账户”；该操作只刷新事实和登记任务，实际交割由后台推进。账户或持仓查询失败时保留上次成功的数量和更新时间，并显示错误；失败不代表空仓。

### 界面语言

在“设置 → 通用设置”选择界面语言，支持简体中文、英语、繁体中文、巴西葡萄牙语、西班牙语、越南语、土耳其语、印尼语、日语、韩语、泰语、世界语和法语。

- 首次按系统语言优先列表选择支持的语言，均不支持时使用英语。选择“跟随系统”可恢复自动选择。
- “跟随系统”固定在列表首位，其余选项按语言原生名称固定排序，切换界面语言时顺序不变。
- 手动选择在词典加载完成后生效并保存在当前设备；存储不可用时仍可在本次会话切换。
- 启动只加载当前语言和英语回退，其他词典在切换时加载并在当前会话缓存。语言资源均随安装包提供，可离线切换。
- 快速切换以最后一次选择为准；加载失败时保留当前语言，启动阶段加载失败时使用英语。
- 切换语言保留当前表单和交易状态；日期仍使用系统本地时区和公历。

## 选择与提交策略

1. 在“双币赢”选择卖 Put 低买或卖 Call 高卖。
2. 按到期日、年化、行权概率或距现价筛选候选，选择合约并输入数量。
3. 查看预计权利金和保本价，在复核窗口确认合约与数量后提交。
4. 在“策略订单”分别查看本机订单历史与交割任务，在“总览”查看卖方净仓与到期日历。

已连接且进入“双币赢”时没有缓存候选，会自动扫描；已有候选通过“刷新候选”更新。修改数量时的权利金和保本价是本地预估，预览成功不代表已通过实时交易检查；提交后以实际成交回报为准。

候选目标价旁的“持仓”标识来自当前卖方净仓。同一合约即使分多笔下单，也只按 Binance 当前净仓展示一份义务；本机成交历史不叠加到净仓数量中。

符合范围的未到期卖方净仓在成功同步后自动登记，无须逐笔选择或确认。若到期前一次成功同步确认该合约已没有卖方净仓，程序停止跟踪这份义务；查询失败不会触发这一判断。

总览日历按合约生成登记、到期和交割事件，并显示待处理的恢复记录。同一合约多笔成交不会重复增加到期事件；提前平仓后，该合约不再显示到期义务。

## 自动交割与恢复

Binance 期权采用现金结算。程序为到期前已成功登记、且此后没有停止跟踪的净仓建立交割任务，按行权事实执行真实现货交易，模拟实物交割：卖 Put 所需的交割买入 BTC，卖 Call 所需的交割卖出 BTC。确认未价内到期（价外或平值）、无需现货动作的任务直接完成。未完成批次会预留资金并限制新策略。

交割资格由本机到期前的登记记录决定：

- **已登记后离线跨过到期**：重新连接后继续核对行权事实并恢复原任务，即使当前持仓接口已不再返回该合约。
- **到期后才首次发现**：不根据历史成交或行权记录新增交割任务，不补做过去的义务。
- **价内但账户行权数量未确认**：继续等待，不使用到期前最后登记数量发送现货订单。等待不等于数量为零。
- **公开结算价确认无需交割**：任务可以直接完成；若账户未提供行权数量和现金结算金额，这些字段仍为空，不推算或补成零。是否还需交割以任务状态为准。

交割任务“已完成”表示现货动作已足额成交，或已确认无需执行。整批任务完成后，至少再等待 5 分钟才开始资金归集；资金收尾结束前继续预留资产并限制新策略。交割明细可核对账户行权金额、现货订单号、成交数量和均价。

保持客户端运行并连接，让后台自动处理交割与资金收尾。**不要在 Binance 网页、其他程序或另一终端手工补齐同一义务，也不要在此账户并行运行其他交割自动化。** 程序不检测或抵扣这些外部补齐，仍会执行已登记任务，可能造成重复买卖；专用账户与不干预是使用约定。

异常在“策略订单 → 恢复中心”处理。请求结果待确认时，系统查询原请求；不能将网络错误当作交易失败直接重发。符合条件的失败收尾可选择“结束理财收尾”，未申购资金留在现货。

保证金门槛、备资顺序、资金预留和人工恢复条件见[实盘交易安全](trading-safety.md)。

## 资产与收益口径

页面上的收益预估不代表最终成交或收益承诺。订单与资金事实来自 Binance 或 SQLite 中的真实记录，日志和前端进度不作为事实依据。

### 资产与持仓

- 同名资产合并展示并保留账户来源；合并后无法完整估值的资产保留数量，不计入总资产估值和比例图。
- 义务仓概览按当前未到期卖方净仓汇总，不按历史订单累加。单个净仓数量以“张”显示，每张 BTC 数量来自合约 `unit`；组合 BTC 数量为 `净仓张数 × unit`，卖 Put 名义本金为 `执行价 × 净仓张数 × unit`。实际保证金占用以 Binance 账户记录为准。
- 总览和“持仓与现货”中的单仓浮动盈亏直接展示 Binance 当前净仓返回的值，供逐合约核对。
- 账户展示缓存不参与下单、备资或恢复判断。

### 本机权利金

- **本机已记录卖出权利金**：只汇总本机保存的已成交期权卖单，按 `实际成交均价 × 已成交张数` 计算，每笔保留两位小数后汇总。部分成交后取消或过期的订单仍按实际成交部分统计；外部建立的净仓不会凭成本均价推算或补记历史权利金。这一金额不是整个 Binance 账户的历史累计收益。
- 收益分析页顶部以两列展示本机已记录和今日卖出权利金，另有卖 Put / Call 分布和成交记录；不统计或展示行权现金流、期权浮动盈亏和补齐 BTC 浮动盈亏汇总。
- 成交保本价按每 BTC 权利金计算：卖 Put 为 `执行价 − 成交均价 ÷ unit`，卖 Call 为 `执行价 + 成交均价 ÷ unit`。不引入手续费计算。
- 日期展示和按日统计使用系统本地时区；“今日已记录卖出权利金”按本机订单的创建日期汇总。到期判断使用合约精确时间。

### 年化预估

年化使用单利估算：

```text
年化（%） = 权利金 ÷（执行价 × 数量基数）× 365 ÷ 到期天数 × 100
```

数量基数为合约张数乘以每张 BTC 数量 `unit`。候选使用预估权利金与扫描时点；本机订单使用成交权利金、已成交数量和记录中的创建时点。到期天数向上取整，至少按 1 天计算。

## 日志与排查

在“设置 → 日志”查看最近记录、打开今日日志或日志目录。文件按本机日期写入应用数据目录下的 `logs/YYYY-MM-DD.log`，每行一条 JSON；消息保存稳定代码与参数，日志面板按当前语言翻译，级别和事件代码保持原值。

日志写入失败只在日志面板反馈，不改变已确认的交易或资金结果。删除日志不影响订单、净仓、交割任务、恢复记录或 keyring 凭据。

反馈问题时附系统环境、复现步骤和脱敏后的错误信息，不附 API 凭据、签名请求或 Binance 原始响应。交易与资金异常先按[恢复规则](trading-safety.md#资金与恢复)核对。
